# 핵심 작업 원칙

## 언어와 소통
- 사용자와의 대화, 계획서, 문서는 한국어로 작성한다.
- 코드, 변수명, 커밋 메시지 제목은 영어(한글)로 작성한다.
- 모르는 것은 추측하지 말고 "확인 필요"라고 밝힌다. 존재하지 않는 API, 설정, 라이브러리를 지어내지 않는다.

## 작업 방식
- 코드를 쓰기 전에 관련 기존 코드를 먼저 읽고, 기존 패턴을 따른다.
- 한 번에 하나의 목적만 다룬다. 리팩터링과 기능 추가를 섞지 않는다.
- 요청이 모호하면 구현 전에 질문한다. 단, 질문은 한 번에 최대 3개.
- 작업 규모 판단:
  - 소: 파일 1~2개, 명확한 변경 → 바로 진행 후 결과 보고
  - 중: 파일 3개 이상 또는 설계 판단 필요 → plan-task 스킬로 계획 후 승인 대기
  - 대: 여러 모듈, DB 변경, 외부 연동 → 계획 + 단계 분할 + 단계별 승인

## 완료의 정의 (Definition of Done)
다음을 모두 만족해야 "완료"라고 보고할 수 있다.
1. 빌드 성공
2. 관련 테스트 추가 또는 수정, 전체 테스트 통과
3. 요청 범위 밖 변경 없음
4. 필요한 경우 docs 갱신 (PROGRESS, DECISIONS)
검증하지 못한 항목이 있으면 "미검증"이라고 명시한다.
