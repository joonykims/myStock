# 적용 가이드

## 1단계 (첫날, 30분)
1. 이 폴더의 AGENTS.md, .agents/, docs/ 를 프로젝트 루트에 복사
2. `{{ }}` 로 표시된 부분을 실제 값으로 채우기 (AGENTS.md, ARCHITECTURE.md 우선)
3. Antigravity 에서 Customizations 패널을 열어 rules 4개와 skills 3개가 인식되는지 확인
4. 새 대화에서 "현재 프로젝트 규칙과 사용 가능한 스킬을 요약해줘"로 로딩 테스트

## 2단계 (첫 주)
- 실제 작업을 시켜보고, 에이전트가 틀린 것을 LESSONS.md 에 기록
- 20-java-spring.md 를 팀 실제 컨벤션에 맞게 수정

## 3단계 (운영)
- LESSONS.md 에서 반복된 항목만 rules 로 승격 (규칙은 "실제로 틀린 것"에서 나와야 한다)
- 규칙 파일이 길어지면 쪼개기 (파일당 12,000자 제한)
- 반복 작업이 생기면 skills 추가 (예: api-scaffold, db-migration, release-note)

## 주의
- 폴더명은 `.agents` (복수형)가 현재 기본. 예전 `.agent` 도 읽히지만 새로 만들 땐 `.agents` 사용
- Workflows 는 2026-11-01 까지 Skills 로 대체될 예정이므로 절차는 skills 로 작성
- rules 의 trigger(항상 적용/파일 패턴/모델 판단) 표기가 버전에 따라 다를 수 있으니, 인식이 안 되면 Customizations 패널에서 활성화 모드를 직접 지정
