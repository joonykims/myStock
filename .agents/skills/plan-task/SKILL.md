# 작업 계획 수립

## 절차
1. docs/PROGRESS.md, docs/ARCHITECTURE.md, 관련 코드를 읽는다.
2. 요구사항을 한국어로 재정리하고, 불명확한 점이 있으면 먼저 질문한다.
3. `docs/plans/YYYYMMDD-작업명.md` 파일을 아래 양식으로 만든다.
4. 사용자에게 계획 요약을 보여주고 승인을 기다린다. 승인 전에는 코드를 수정하지 않는다.
5. 승인되면 docs/PROGRESS.md 의 "진행 중"에 이 계획서를 링크한다.

## 계획서 양식
```markdown
# {작업명}
- 상태: 계획 | 진행중 | 완료 | 보류
- 작성일: YYYY-MM-DD

## 목표
무엇을, 왜 하는지 2~3줄

## 범위
- 포함:
- 제외:

## 영향 받는 파일
- path/to/File.java — 변경 이유

## 단계
- [ ] 1. ...  (검증: 어떤 테스트/명령으로 확인하는지)
- [ ] 2. ...

## 위험 요소와 대응
- 

## 확인이 필요한 질문
- 
```

## 원칙
- 각 단계는 독립적으로 빌드/테스트 가능한 크기로 쪼갠다.
- 모든 단계에 검증 방법을 적는다. 검증 방법이 없는 단계는 계획이 덜 된 것이다.
